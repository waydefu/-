Date: 2026-05-26

- Keep existing ARIA, focus-visible, skip-link, reduced-motion, and 44x44 touch target support.

## Research Notes

- MDN stacking context / z-index: positioned elements and descendants must be layered inside the same stacking context; pseudo-element plates need clear `z-index` order and content above them.
  Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Positioned_layout/Stacking_context
- MDN `z-index`: higher stack levels cover lower ones only for positioned elements / flex-grid items in the same context.
  Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/z-index
- web.dev animation performance: keep UI animation on `transform` and `opacity` for smoother rendering; avoid layout-changing animation for panels.
  Source: https://web.dev/articles/animations-and-performance
- MDN `animation-fill-mode`: use `both` / `forwards` when the start or final animation state must be visible before/after the animation.
  Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-fill-mode
- MDN `prefers-reduced-motion`: preserve reduced-motion path and avoid forcing motion for users who request less movement.
  Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion
- MDN `clamp()`: use min/preferred/max constraints for responsive type and spacing without letting mobile text shrink below a readable floor.
  Source: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp
- W3C WCAG 1.4.4 Resize Text: text and text-based controls must scale to 200% without loss of content/functionality.
  Source: https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html
- W3C WCAG 1.4.10 Reflow: content must work at 320 CSS px width without two-dimensional scrolling for normal content.
  Source: https://www.w3.org/WAI/WCAG22/Understanding/reflow.html
- W3C WCAG 2.5.5 Target Size Enhanced: keep custom targets at least 44 by 44 CSS px, especially on touch screens.
  Source: https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html

## Implementation Plan

1. Button plate correction
   - Create a more forceful `.sao-btn` plate rule near the end of CSS so older nav/account/history/dossier styles cannot override it.
   - Make cyan offset visible with a larger, responsive plate offset and z-index below the main plate.
   - Keep content above plates using direct-child stacking and no id changes.
   - Hide `.sao-btn-tag` on compact/nav/mobile buttons where it crowds labels.

2. Login CTA cleanup
   - Remove the visible `G` mark from `#openRitualBtn` only.
   - Keep the Google login label, id, form, Auth behavior, and accessibility name.

3. SAO materialization visibility
   - Lengthen login panel and workbench panel materialization enough to be perceptible.
   - Add a clear point-to-horizontal-line-to-vertical-panel sequence for login and workbench with transform/opacity only.
   - Keep reduced-motion path showing the final state without forced motion.

4. Laptop and mobile workbench spacing
   - Reduce the vertical gap between workbench title/copy and the input area.
   - Collapse the tall empty mobile top navigation shell; nav buttons should sit compactly without creating a large empty panel.
   - Raise mobile minimum type sizes for operational text and result/dossier text.

5. Validation
   - Sync worldforge.
   - Run `npm run test:visual:update` or force refresh if snapshots do not rewrite.
   - Run `npm run check`, `npm test`, `npm run test:a11y`, `npm run build`, and `git diff --check`.
   - Review desktop and mobile screenshots, including login, workbench, account/history, and result/dossier states.

## Expected Risk

- High visual-diff churn in snapshots because button layering and mobile spacing change globally.
- Medium risk of crowded mobile nav buttons if cyber plate offset/tag is too large.
- Low behavior risk because the change is CSS/layout-focused and must not modify Firebase/Auth/draft/history logic.

### 2026-05-27 Dev.to Button Article Review

Source reviewed: https://dev.to/jh3y/css-cyberpunk-2077-buttons-taking-your-css-to-night-city-43l0

Design interpretation after reading:

- The core effect is not a glow; it is two clipped plate layers.
- The article stacks `::before` and `::after` with the same `clip-path`; the lower layer is translated to create a real offset backing plate.
- The final article clip includes a bottom-right cutout because the `R25` tag occupies that space.
- If the tag is removed, keeping the tag cutout is visually wrong because it leaves a purposeless bite/notch in the lower-right button edge.
- The glitch layer should be a duplicate text layer revealed only on hover/focus, with animated `clip-path` slices and lateral shimmy.
- Decorative duplicate text and tags must stay `aria-hidden`.
- For this project, the technique should be adapted to black/gold/bronze rather than copied as red/cyan Cyberpunk 2077 colors.

Follow-up correction before editing:

- Replace the tag-notched clip path with a no-tag clipped shape.
- Update the glitch slice clip variables to match the no-tag shape.
- Preserve the real offset backing plate, current ids, Auth/history/draft behavior, 44px targets, and reduced-motion support.

Completed after article review:

- Updated `public/index.html`, then synced `public/worldforge-login.html`.
- Removed the tag cutout from `--sao-cyber-clip`.
- Updated `--sao-glitch-clip-*` variables to match the no-tag clipped button shape.
- Re-ran visual snapshots and reviewed login, mobile workbench, and account menu states.
